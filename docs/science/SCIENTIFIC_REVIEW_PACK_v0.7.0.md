# Scientific Review Pack — OCEAN / iOceans Controlled Evolution Mockup v0.7.0

## Purpose

This document is intended for scientific review.

The mockup does not attempt to prove scientific results. It shows how scientific evidence, operational records, review states, audit logs and governed AI actions could be structured before real OCEAN data is connected.

The goal is to make the operating model inspectable by scientists, engineers and decision makers.

## Core principle

Scientific information should not enter the system as a vague document or dashboard item.

It should enter as a controlled evidence object with:

- Source
- Method
- State
- Review status
- Data classification
- Audit reference
- Human responsibility
- Interpretation limits
- Reproducibility notes
- Downstream decision boundaries

## What scientists should evaluate

Scientists reviewing this mockup should not evaluate it as a finished scientific platform.

They should evaluate whether the proposed operating model is suitable for future scientific work.

The key questions are:

- Can evidence be traced back to its origin?
- Can the method behind an evidence asset be recorded?
- Can review status be separated from operational status?
- Can AI assistance be constrained and audited?
- Can uncertainty be represented without becoming a false conclusion?
- Can logs explain who did what and why?
- Can the system prevent unsupported scientific claims?
- Can evidence, interpretation and decision remain separate?
- Can future real data be introduced without losing provenance?

## Evidence lifecycle

A scientific evidence asset should move through explicit states.

Example lifecycle:

```text
received
pending_review
approved
requires_decision
blocked_by_risk
```

The state should never be hidden inside a visual dashboard.

The state should be visible, auditable and explainable.

## Evidence is not a conclusion

The mockup distinguishes between:

```text
raw input
evidence asset
reviewed evidence
interpretation
decision
external report
```

This separation matters because a system that mixes evidence and conclusion too early can create misleading outputs.

## AI governance

AI is treated as an assistant, not an authority.

Allowed AI roles:

- Summarize synthetic evidence
- Flag missing review metadata
- Suggest internal next steps
- Draft non-binding report text
- Explain uncertainty and risk flags

Forbidden AI roles:

- Produce final scientific conclusions
- Replace scientific review
- Hide uncertainty
- Call external APIs without approval
- Use real data without explicit governance
- Perform autonomous commercial outreach
- Generate binding operational decisions

## Scientific guardrails

The mockup is designed around these guardrails:

- No real scientific measurements
- No real OCEAN data
- No real customer data
- No production telemetry
- No external API calls
- No unsupported conclusions
- No hidden AI action
- No evidence asset without audit reference
- No report without review status
- No executive action without decision gate

## Why this matters for OCEAN

OCEAN operates in a domain where scientific credibility, field evidence, ecological impact, operational execution and reporting may converge.

That convergence creates a risk: dashboards can make outputs look more certain than the underlying evidence allows.

The proposed model reduces that risk by making the evidence chain explicit.

## Review model

Each relevant object should answer:

```text
What is it?
Where did it come from?
Who introduced it?
What method produced it?
What state is it in?
Who reviewed it?
What can AI do with it?
What can AI not do with it?
What log records the action?
What decision depends on it?
```

## What this mockup is not ready for

The mockup is not ready for:

- Real OCEAN data
- Real credentials
- Real integrations
- Production users
- Production telemetry
- Scientific publication
- Regulatory claims
- Automated external reporting

## Recommended scientific review questions

Recommended questions for OCEAN scientists:

- What types of scientific evidence should exist in phase 1?
- Which metadata is mandatory for each evidence asset?
- Which methods must be represented explicitly?
- Which uncertainty fields are required?
- Which review states are scientifically meaningful?
- Which evidence objects can be summarized by AI?
- Which evidence objects must never be touched by AI?
- Which reports require human scientific approval?
- Which logs are required for scientific defensibility?
- Which outputs could be misleading if shown too early?

## Target outcome

The target outcome of this review is not approval of a final product.

The target outcome is agreement on the first operational data model that OCEAN could trust.
