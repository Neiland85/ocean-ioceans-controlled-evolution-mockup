# Scientist Review Checklist — OCEAN / iOceans Mockup v0.7.0

## Review objective

Use this checklist to evaluate whether the mockup represents a credible operating model for scientific evidence, operational traceability and governed AI.

## Evidence model

- Are the evidence objects understandable?
- Is the source of each evidence object clear?
- Is the review status visible?
- Is the audit reference visible?
- Is the evidence separated from interpretation?
- Is the evidence separated from decision making?

## Method traceability

- Can a future method be attached to each evidence object?
- Can the system distinguish field measurement, derived indicator and report output?
- Can uncertainty be represented explicitly?
- Can a reviewer understand what produced the evidence?

## AI boundaries

- Is AI clearly constrained?
- Is human approval required?
- Are forbidden AI actions explicit?
- Is there an audit trail for AI-assisted actions?
- Is there a clear distinction between AI summary and scientific conclusion?

## Operational fit

- Does the model help connect scientific evidence with operational execution?
- Does the model help avoid unsupported claims?
- Does the model help explain why something is approved, blocked or pending?
- Does the model support future reporting?

## Risks to discuss

- Which scientific claims should never be generated automatically?
- Which evidence types require senior review?
- Which fields are mandatory before reporting?
- Which objects require immutable logs?
- Which uncertainty labels are required?

## Decision after review

After review, classify the mockup as:

```text
A. Suitable operating model for phase 1 discussion
B. Suitable with changes to evidence metadata
C. Suitable with changes to review states
D. Not suitable without deeper scientific redesign
```

## Recommended next step

If the model is suitable, define the first real phase around a limited number of entities, states and review gates.

Do not connect real data until the evidence model is agreed.
